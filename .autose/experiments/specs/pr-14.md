## Goal
Add an optional `limit` argument to `search()` so callers can ask for at most n matching documents.

## Current behaviour
`search(cond)` returns all matching documents; callers slice the list themselves.

## Requirements
- FR-1: `search(cond, limit=n)` returns at most n matching documents, in the order `search()` normally returns them.
- FR-2: Without `limit`, `search()` behaves exactly as today.
- FR-3: A negative `limit` is rejected.

## Acceptance criteria
- **AC-1** (FR-1) [CONFIRMED]: Given 10 matching documents, when `search(cond, limit=5)` is called, then the first 5 matching documents are returned in order.
- **AC-2** (FR-1) [INFERRED]: Given 10 matching documents, when `search(cond, limit=50)` is called, then all 10 are returned.
- **AC-3** (FR-2) [CONFIRMED]: Given 10 matching documents, when `search(cond)` is called, then all 10 are returned.
- **AC-4** (FR-3) [INFERRED]: Given any table, when `search(cond, limit=-1)` is called, then a ValueError is raised.

## Assumptions
- [INFERRED] The limit is applied to the result list after matching; the query cache keeps working as before.

## Open questions
- Should `limit=0` return an empty list? Assumed yes.

## Out of scope
- Offsets / pagination.
