## Goal
Make the built-in update operations work on documents that do not have the field, instead of raising KeyError.

## Current behaviour
`increment`, `decrement`, `add`, `subtract` and `delete` raise KeyError when a document lacks the field.

## Requirements
- FR-1: `increment`/`decrement`/`add`/`subtract` treat a missing numeric field as 0.
- FR-2: `delete` skips documents that do not have the field.
- FR-3: Documents that already have the field behave as before.

## Acceptance criteria
- **AC-1** (FR-1) [CONFIRMED]: Given docs with visits=5 and without visits, when `update(increment('visits'))` runs, then visits are 6 and 1.
- **AC-2** (FR-1) [CONFIRMED]: Given the same docs, when `update(add('visits', 10))` runs, then visits are 15 and 10.
- **AC-3** (FR-1) [INFERRED]: Given the same docs, when `update(decrement('visits'))` runs, then visits are 4 and -1.
- **AC-4** (FR-2) [CONFIRMED]: Given one doc with 'tag' and one without, when `update(delete('tag'))` runs, then no doc has 'tag' and both docs remain.

## Assumptions
- [CONFIRMED by maintainer comment] Missing numeric fields count as 0; delete skips.
- [INFERRED] `add` with a string on a missing field starts from that string.

## Open questions
- None.

## Out of scope
