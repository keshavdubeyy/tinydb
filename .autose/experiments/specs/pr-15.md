## Goal
After a table is dropped, table objects that callers still hold must not keep returning the dropped data from their query cache.

## Current behaviour
`drop_table` forgets the table object but its query cache still holds old results.

## Requirements
- FR-1: `drop_table(name)` clears the query cache of the open table object before forgetting it.
- FR-2: `drop_tables()` clears the query caches of all open table objects.

## Acceptance criteria
- **AC-1** (FR-1) [CONFIRMED]: Given a table 'users' with one document, when `db.drop_table('users')` is called, then 'users' is no longer in `db.tables()`.
- **AC-2** (FR-2) [INFERRED]: Given a database with a table that has documents, when `db.drop_tables()` is called, then `db.tables()` is empty and no error is raised.

## Assumptions
- [INFERRED] Clearing the cache with the existing `Table.clear_cache()` is enough.

## Open questions
- None.

## Out of scope
- Re-creating dropped tables automatically.
