## Goal
Make `update()` all-or-nothing, so that an update function that fails part-way leaves every document unchanged, and keep bulk writes fast.

## Current behaviour
With MemoryStorage, documents updated before the failing one stay changed. Each JSON write also calls fsync, which makes the extra copying for atomic updates and bulk inserts slow.

## Requirements
- FR-1: If the update function raises for any document, no document is changed (`update` and `update_multiple`).
- FR-2: Successful updates behave as before.
- FR-3: Remove the per-write `os.fsync` call in `JSONStorage.write` so that bulk inserts and the copy-based updates stay fast.

## Acceptance criteria
- **AC-1** (FR-1) [CONFIRMED]: Given 4 documents where the third makes the update function raise, when `db.update(fn)` is called, then all 4 documents are unchanged.
- **AC-2** (FR-1) [INFERRED]: Given the same documents, when `db.update(fn, cond)` is called, then all documents are unchanged.
- **AC-3** (FR-1) [INFERRED]: Given the same documents, when `db.update_multiple([(fn, cond)])` is called, then all documents are unchanged.
- **AC-4** (FR-2) [CONFIRMED]: Given 2 numeric documents, when a valid update runs, then both are updated.

## Assumptions
- [INFERRED] The OS flushes file data soon enough; fsync on every write is not needed for TinyDB's use cases (FR-3).

## Open questions
- None.

## Out of scope
- Transactions across tables.
